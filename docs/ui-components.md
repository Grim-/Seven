# Shared UI components and hooks

Use these instead of writing the pattern again. Add every new shared piece here in the same change.

## Helpers
- `lib/notify.ts`: `failed(what)` error toast handler, `copyText(text, label, shown)` clipboard with toast.
- `store/toasts.ts`: `toast.info` / `toast.success(title, message, action)`; `action` (`{ label, onSelect }`) shows a button on the toast. Adding or importing anything never switches views: the toast's Open button is the way there.
- `lib/useBusy.ts`: `useBusy()` returns `[busy, run]` for actions with a busy flag and error toast.
- `lib/useFileDrop.ts`: `useFileDrop(onPaths, enabled)` gives drag props and an `over` flag for dropping files; `onPaths(paths, e, dropped)` also gets each `DroppedFile` (`path`, `file`); inner drop targets win. `ui/DropOverlay.tsx`: `DropOverlay` shows the drop hint. `lib/importFiles.ts`: `importPaths(paths, parent)` adds files (into a folder if given) and checks pictures for carried data, `addPaths(paths, parent)` adds them without that check, `chooseFiles(parent)` opens the file picker and adds them. `lib/dropFiles.ts`: `dropFiles(dropped, ask)` a drop on the window; `placePictures(dropped, ask)` puts pictures in the dropped-pictures folder or asks where (`components/files/DropPictures.tsx`); `importInto(dropped, folder)` makes the folder path if missing and adds them.
- `lib/useObjectUrl.ts`: `useObjectUrl(blob)` a URL for a File or Blob, revoked when it changes or unmounts.
- `components/files/FolderInput.tsx`: `FolderInput({ value, onChange })` a folder path box suggesting existing folders.
- `lib/useLive.ts`: `useLive(fetch, event)` loads a value and reloads it whenever the engine event fires.
- `lib/listPrefs.ts`: `useListPrefs(key, fallback)` for a remembered open/width side list.
- `lib/window.tsx`: `WindowProvider`, `useWindowId()`, `useLocation(fallback)` for what a window shows. Never keep a window's selection in a global store.
- `lib/conversation.ts`: `useConversation()` for the chat a component sits in, `useFocusedConversation()` for the chat you're in, `useAgentIdOf(conv)`, `openChat(id, agentId?)`.
- `lib/composer.ts`: `queueComposer(key, text, replace?)` puts text in a chat's composer, now or when it next shows; `lib/conversation.ts`: `referenceInChat(link)`, `startChatWith(agentId, link)`.
- `lib/library.tsx`: `showInData(selection, show?)`, `openEntry(kind, id)`.
- `lib/kinds.ts`: `useKindInfos(enabled?)` cached list of kinds (label, description, parts); `loadKindInfos()`.
- `@shared/text`: `textLines`, `linkFor`. `@shared/ids`: `toId`, `showName`, `isAssetId` (the one file id check), `ASSET_IDS_IN` (file ids inside text). Main process saves go through `askSavePath` in `main/ipc.ts` (`dialog.savePath` from the renderer).
- `store/data.ts`: `entryLink(kind, id)` gives the @link for any entry, using the folder path for pages.
- `components/chat/changeAgent.ts`: `changeAgent(agent, patch, what)` saves an agent change and reloads the open chat's context.

## Saving
- `ui/autosave.tsx`:
  - `useAutosavedState(initial, save, { when })`: value that saves itself as it changes.
  - `useDraft(source, save, { valid })`: same, following an outside source until edited.
  - `useAutosave(save)`: the base saver.
  - `SaveState`: Saving / Saved / Not saved, with `blocked` for validation.
  - `MakeOrSaved`: Make button until the thing exists, then the save status.
  - `DoneEditing`: save status and a Done button that saves first.

- `lib/importFiles.ts`: `choosePictures(kinds, multiple, what)` pick files from disk into the library; `onlyKinds(added, kinds, what, mimes?)` keep the ones that fit and say which didn't; `fitsFile(asset, kinds, mimes?)`. Every import of files from disk goes through `importPaths` or `addPaths` (`dropFiles` for a drop on the window is in `lib/dropFiles.ts`).
- `components/backdrop/backdropActions.ts`: `setBackdrop(scope, backdrop, sessionId, minutes?)` and `BACKDROP_SCOPES`.
- `components/slideshow/`: `useSlideshows()`, `useSlideshow(id)`, `newSlideshow(pictures, then)`, `addToSlideshowMenu(pictures)`, `SlideshowPlayer`.
- `components/slideshow/`: `SlideshowPlayer({ id, controls })`, `addToSlideshowMenu(pictures)`.
- `ui/PaneHeader.tsx`: `PaneHeader({ title, titleHint, count, onTitle, onTitleMenu, back, children })` the header of a side column: optional back row, title (click and right-click), count, and action buttons as children (ghost `Button`s).
- `views/data/entryMenu.tsx`: `exportMenuAt(e, section, open?)` the Export menu for a kind, with the open entry first.
- `views/data/entryMenu.tsx`: `entryMenuAt`, `rowMenu(kind, id, title, open, extra)`, `kindMenuAt`.
- `ui`: `KindShell` (entries as `layouts`: `tiles` (`ShellTiles`, icon or thumbnail first), `cards` (`ShellCards`, title, subtitle, excerpt, small icon or thumbnail), `list` (`ShellRows`), `gallery` (`ShellGallery`, holo tiles: glowing glyphs, pictures with clipped corners), `deck` (`ShellDeck`, each item as a card: the item's `face` if it has one, else a `ShellFace` built from its tag, thumb, title, subtitle and excerpt; `count` shows a ×count badge). Tiles are notched data slates, list is a numbered manifest, cards and deck borrow the slate; all styled by the `shell-*` classes in `theme/components.css` and the pieces in `ui/ShellParts.tsx` (`shellState`, `ShellIcon`, `ShellAddTile` the add tile, `FaceGrid({ scale })` the grid of faces, `FaceCount({ count })`). An item's `tag` is its type code (DIR, PAGE, PNG); default cards and list. A layout is a `View` in `LAYOUTS`; every view gets `scale` from the Size control (a typed percentage, 100 = base sizes). Layout, sort and size are remembered per `id`, falling back to `inherit` (each folder uses `pages.<folder>` inheriting `pages`). `pickable` turns on Ctrl/Shift picking (`lib/picking.ts` `pickWith`, shared with the Pages list); `onMenu(e, item, picked)` gets the picked keys and `onMove(keys, target)` all dragged keys; picked and drop-target items carry `data-on`. `sorts` replaces the name / newest sort buttons with the screen's own (`ShellSort { id, title, icon, compare }`, `DEFAULT_SORTS` the two defaults); `groups` (`ShellGroup { label, note, adds }`, indexed by each item's `group`) shows headed sections, each with its own add tiles; an item's `aside` replaces its changed time (the list column is `asideLabel`, read through `asideOf(item)`) and `color` tints its default deck face; `onDouble(item)` on double-click; `filter={false}` hides the local filter box when the header has its own search. `onOpen(item, shown)` (optional) gets the items in shown order (a folder opens a file, picture or not, in its file view, the same as the menu's Open); its `adds` show as buttons and as the right-click menu on empty space, with `children` for a submenu), `useReorder` / `moved`.
- `ui/ShellFace.tsx`: `ShellFace({ title, label, tags, marks, aside, art, type, body, stats, foot, corners, color, frame })` the one card face, a shell slate with slots: header (`label` text, `tags` left, `marks` or `aside` right), `art`, title, type line, body, `stats` strip, `foot`; `frame` notched, rounded or playing (`corners` for the playing corners); `color` tints it. Fills its container's width. A kind gives its own face with `KindUi.face({ id })`, which the Pages list and kind lists use for the deck layout.
- Remembering where you were: `usePlaces` (`store/places.ts`, saved in the vault through `places.get` / `places.set`) holds small bits of view state by key; `save(key, value)` only writes once they've loaded. `useRememberedLocation(fallback)` (`lib/window.tsx`) is `useLocation` that survives restarts (the Data tab). A kind with `KindUi.start` is where the Data tab opens the first time (Files). The Files tree keeps its open folder, expanded folders and tab under `pages.tree`.
- `lib/useNow.ts`: `useNow(every, running)` the current time, ticking while `running` (clocks, timers). `lib/reminders.ts`: `useReminderList()` the live reminder list and its load error (reminders page, Today glance, timer card).
- Chat parts for fixed inline presentation tools (`components/present/`): `Suggestions` (suggest: reply buttons that send the reply), `TimerCard` (timer: a `ShellFace` counting down to its reminder, with Stop), `Aside` (aside: a side remark beside the reply). Each registers itself with `registerPresentation`.
- `ui/SecretField.tsx`: `SecretField({ set, onSave, placeholder })` a password box with Save and Remove for a key kept in the vault (add-on keys, the Hugging Face token).
- `lib/systemStats.ts`: `useSystemStats(every)` polled CPU, RAM and VRAM (status bar, System glance, download fit); `gigabytes(bytes)`. `lib/format.ts` also has `formatCount` (412K, 12B) and `formatDuration` (1m 03s).
- `components/models/`: `memoryFit(size, stats)` whether a file fits free VRAM, VRAM + RAM, or neither, with the reason; `HubSearch` (Hugging Face GGUF search in a `KindShell`, `filter={false}` since the search box queries the site), `HubRepo` / `HubFileRow` (a repo's files with fit, header-read imatrix and context, Save to, token), `DownloadsCard` (background downloads with progress, pause, resume, cancel), `ModelTraits` / `modelTraits(info)` (MoE, MTP and imatrix badges from a GGUF header, with their reasons; used for local models and Hugging Face files). Search filters (`hubMatches`, `HUB_SIZES`) live in `store/hub.ts`; `isMoeArchitecture` in `@shared/types`. Stores: `store/hub.ts` (search results, files and headers per repo), `store/downloads.ts` (live list; a finished download rescans the model folders).
- Views remember where they were: `useViewPlace(key, fallback)` (`lib/viewPlace.ts`) is state shared across a window and saved in the vault under `view.<key>`, restored on reopening; `setViewPlace(key, value)` sets it from outside React (Models tab, selection and Download page, Agents, Tools, Settings section, the open dashboard). Use it for any view state the user would expect back; check the remembered thing still exists before going back to it.
- Facets (`lib/facets.ts`): a `Facet<T>` is a `choice` (options, `test(item, value)` returning true, false, or null while not known yet) or a `max` (a slider with `measure(item)`). `applyFacets(items, facets, values)` gives `shown` and `pending`; `useFacetValues(key)` remembers the picks; `ui/FacetBar.tsx` draws them (Segmented choices, SliderNumber maxima) with a summary slot. Model facets (`components/models/modelFacets.ts`: Type dense or MoE, MTP, Quant, Max size) and Hugging Face facets (`hubFacets.ts`) are built from header facts.
- `ui/TraitChips.tsx`: `TraitChips({ traits })` small toned chips; a `ShellItem` can carry `traits` and every shell layout shows them. `modelTraits(info)` gives a model's (Dense or MoE n×k, quant, MTP, imatrix).
- GGUF facts come from the header only (`engine/model/gguf/`): `read.ts` `readHeader(source, { size })` reads a local path or `hf:` file; `classify.ts` maps every `ModelInfo` field to one resolver (`facts/kind`, `quant` from `general.file_type`, `experts`, `mtp`, `imatrix`, `split` from `split.no`/`split.count`, `chatTemplate`); the size is node-llama-cpp's `GgufInsights.modelSize` over all parts. No file-name checks.
- `ui/BackBar.tsx`: `BackBar({ onBack, kind, children })` the Back bar over an opened entry (browse in a `KindShell`, open full width, Back returns): Agents, Tools, Models, the panel browser.
- `ui/CountStepper.tsx`: `CountStepper({ value, onChange, min, max, small })` minus, count, plus.
- `ui/TileIcon.tsx`: `TileIcon({ shape: 'folder' | 'page' | 'file', label, glyph })` sharp large icon for grid tiles; a page can carry a small kind glyph, a file its extension. Pass it as a `KindShell` item's `tile`.
- `components/data/PageView.tsx`: `newPageItems(types, onCreated, parent)` menu items for making a page of any type; `newPageMenu` opens them.

- `modules/core/things.ts`: `thingsFrom(value, ctx)` and `resolveThings(things, onBoard, kctx)` turn links and paths into what show and add_to_board place.
- `engine/tools/signature.ts`: `toolGuide(tool)` a tool's line in its module's guide page, built from its definition: signature, description, each parameter's type, null and description (nested fields too); `paramType`, `toolSignature`. Write a tool's instructions in its description and parameter descriptions; a module's help.md holds only what spans its tools.
- `engine/tools/shown.ts`: `canShowPaths`, `registerShownFile`, `registerHtml` for tools that show workspace files or HTML (show, workout).
- `engine/web/page.ts`: `linkedText(html, url)` a page as plain text with its links kept as [title](address) (web search results); `pageText` the readable article text.
- `engine/data/importing.ts`: `importToLibrary(paths, parent)` adds files to the library, markdown files as pages; renderer `importToLibrary` (`lib/importFiles.ts`) toasts what became pages and what failed. Add files and drops on the window use it; attaching to a chat keeps files as files.
- `registries/drafts.tsx`: `registerDraftPreview(tool, Component)` a live preview of a tool call while the model writes it (think and reason show their reasoning as it streams, `components/mind/ThoughtDraft.tsx`); presentations preview themselves.
- Model fixes (`engine/model/wrappers.ts`): each fix says which chat formats it fixes (`appliesTo`); `wrapperForFile` resolves a model's format from its file header and chat template setting, so only the fixes that apply are listed, and they're on unless turned off.
